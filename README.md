# خزنة (Khazna) v2.0 — مدير كلمات مرور محلي ١٠٠٪

**خزنة** هو مدير كلمات مرور وبطاقات بنكية وملاحظات مشفّرة مصمم ليعمل:
1. **كنسخة أندرويد حقيقية (APK)** تدعم البصمة البيومترية الحقيقية مع اختصار لوحة الإشعارات (Quick Settings Tile) لفتح نافذة عائمة سريعة (Floating Pop-up) تدعم التثبيت فوق الشاشة لسهولة النسخ واللصق.
2. **كنسخة كمبيوتر مباشرة** تعمل في أي متصفح بنقرة واحدة دون اتصال بالإنترنت ودون الحاجة لتثبيت أي خوادم خارجية.
3. **كإضافة لمتصفح جوجل كروم (Chrome Extension)** للوصول السريع إلى خزنتك.
4. **كتطبيق ويب تقدمي (PWA)** قابل للتثبيت محلياً على الهواتف والأجهزة اللوحية.

> **الأمان المطلق**: بياناتك مشفّرة بـ AES-256-GCM + Argon2id ولا تغادر جهازك أبداً. صفر خوادم خارجية، صفر تتبع، وصفر تسريب.

## 🌟 الميزات الجديدة في الإصدار 2.0

- 🎯 **إزالة زر التثبيت من الشريط العلوي**: تم نقله بالكامل إلى داخل شاشة الإعدادات لتوفير واجهة هادئة وأنيقة.
- ⚡ **زر النسخ المزدوج الفوري**: بنقرة واحدة يتم نسخ اسم المستخدم وكلمة المرور معاً للحافظة.
- ⇄ **نقل كلمات المرور بين الأقسام**: زر نقل سريع (`⇄ نقل`) على كل بطاقة، مع دعم نقل العناصر المتعددة دفعة واحدة في وضع التحديد الجماعي.
- 🎨 **ثيمات مخصصة لكل قسم**: لكل قسم لونه وتأثيره الزجاجي ولمعانه الخاص في الوضعين الداكن والفاتح.
- 🗂️ **عرض منظم وأشيك لكلمات المرور**: تجميع أنيق حسب الأقسام مع إمكانية طي وتوسيع الأقسام بنقرة واحدة، وبانر هيرو خاص بكل قسم.
- 📱 **نسخة APK للأندرويد مع لوحة إشعارات منبثقة**: اختصار سريع في لوحة الإشعارات (Quick Settings Tile) يفتح خزنة كنافذة عائمة صغيرة (Floating Popup) فوق التطبيقات تدعم البقاء فوق الشاشة لنسخ البيانات ولصقها بسهولة وأمان.
- 🧩 **إضافة كروم (Chrome Extension)**: Manifest V3 جاهز للاستخدام والتثبيت في Chrome و Edge و Brave.

## ١. لماذا خزنة؟ (الأولويات الهندسية)

1. **الأمان والتشفير صفري المعرفة (Zero-Knowledge)**:
   - تشفير كل البيانات الحساسة في IndexedDB (كلمات المرور، البطاقات، الملاحظات، المسودات، وحتى أسماء الأقسام) باستخدام **AES-256-GCM** مع متجه ابتدائي عشوائي **96-bit IV** لكل عملية تشفير وبيانات مصادقة إضافية (**AAD**) تربط `vaultId + id + type + schemaVersion`.
   - مفتاح تشفير البيانات **DEK (256-bit)** يُولَّد عشوائياً ويبقى في الذاكرة فقط كـ `CryptoKey` غير قابل للاستخراج (`extractable: false`)، ولا يُخزَّن إلا بصيغ ملفوفة (Wrapped) بثلاث طرق مستقلة:
     - **كلمة المرور الرئيسية** (١٢ حرفاً فأكثر، بدون تلميح): عبر **Argon2id (RFC 9106)** بذاكرة لا تقل عن `32 MiB` وتكرارات `>= 3` معايرة زمنياً (~١ ثانية)، أو **PBKDF2-HMAC-SHA-256** (`600,000+` دورة) كخيار احتياطي فقط إذا تعذّر Argon2id.
     - **بصمة الإصبع (WebAuthn PRF)**: ربط تشفيري حقيقي حيث يشتق ناتج امتداد `prf` عبر `HKDF-SHA-256` مفتاح لف للـ DEK مع اشتراط التحقق البيومتري (`userVerification: "required"`). وفي حال عدم دعم الجهاز أو المتصفح لامتداد PRF، يظهر تحذير واضح ويُعرض خيار **وضع الراحة** (يحتفظ بالنسخة في الذاكرة المؤقتة فقط ويتحقق من التوقيع الرقمي `ECDSA/RS256` مع فرض كلمة المرور الرئيسية عند كل تشغيل بارد وكل ٢٤ ساعة، ويمكن تعطيله في أي وقت).
     - **مفتاح الاسترداد لمرة واحدة (256-bit)**: يُعرض مرة واحدة بصيغة Base32 من ١٤ مجموعة مع رمز تحقق SHA-256 (24-bit) مع خيار النسخ والطباعة وتأكيد صريح "لقد حفظته".
2. **الموثوقية وعدم فقدان البيانات**:
   - طلب التخزين الدائم `navigator.storage.persist()` وعرض حالته في الإعدادات.
   - قفل الكتابة المتزامنة عبر **Web Locks API** ومزامنة القفل الفوري بين التبويبات عبر **BroadcastChannel**.
   - **لقطات مشفّرة دوّارة (Rolling Snapshots)** قبل كل عملية استيراد أو تعديل جماعي مع إمكانية التراجع/الاستعادة.
   - **فحص صحة الخزنة** لفك تشفير كل سجل والتحقق من سلامته دون كشفه.
3. **الشفافية والصدق التقني**:
   - عدم ادّعاء أي ميزة أمان لا يدعمها المتصفح فعلياً (راجع قسم **حدود المنصة ونموذج التهديد** بالأسفل).

## ٢. البنية التقنية الصارمة

- **Vanilla HTML / CSS / JS (ES Modules)** فقط — لا أطر عمل (لا React ولا Next.js)، لا CDN، لا خطوط أو صور خارجية.
- **سياسة أمن محتوى صارمة (CSP)** في `index.html` وملف `_headers`:
  ```
  default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; manifest-src 'self'; worker-src 'self'; base-uri 'none'; form-action 'none'
  ```
- **صفر `innerHTML`** وصفر `style="..."` أو سكربتات مضمّنة في كامل المشروع (بناء DOM برمجياً بـ `textContent` و `document.createElement` فقط).
- **تحديثات محكومة بالمستخدم**: الـ Service Worker لا يستبدل الكود بصمت أبداً؛ بل يعرض إشعار «يتوفر إصدار جديد» ولا يفعّله إلا بعد تأكيدك الصريح، مع عرض إصدار التطبيق وبصمة **SHA-256** لملفات التطبيق في الإعدادات.

## ٣. النشر والاستضافة الساكنة (HTTPS)

يتطلب WebAuthn (بصمة الإصبع) والـ PWA نطاق **HTTPS** (أو `localhost` للتجربة). المستضيف يقدّم ملفات الكود الساكنة فقط ولا يصله أي بايت من بياناتك.

### أ) النشر على Cloudflare Pages أو Netlify (موصى به — يدعم `_headers` تلقائياً)
1. ارفع الملفات (أو اربط مستودع GitHub).
2. إذا استضفت الملفات مباشرة دون بناء، حدد مجلد النشر `.` (الجذر)، أو شغّل `npm run build` وحدد `dist`.
3. سيجري تطبيق ملف `_headers` تلقائياً بترويسات `Content-Security-Policy` و `Referrer-Policy: no-referrer` و `X-Content-Type-Options: nosniff` و `Permissions-Policy`.

### ب) النشر على GitHub Pages
1. ارفع المشروع إلى مستودع GitHub.
2. من **Settings → Pages** اختر الفرع الرئيسي والمجلد الجذري `/` (أو `dist` عبر GitHub Actions).
3. جميع المسارات نسبية (`./`) لتعمل بسلاسة سواء على نطاق جذري أو فرعي مثل `https://username.github.io/khazna/`.
4. ملاحظة: GitHub Pages لا يقرأ ملف `_headers`، لذا يعتمد تلقائياً على `<meta http-equiv="Content-Security-Policy">` و `<meta name="referrer" content="no-referrer">` المدمجين داخل `index.html`.

## ٤. التثبيت على Android كـ PWA

### على Google Chrome (الأفضل لدعم WebAuthn PRF)
1. افتح رابط التطبيق عبر HTTPS.
2. اضغط زر **تثبيت التطبيق** داخل الإعدادات، أو من قائمة كروم (**⋮**) اختر **الإضافة إلى الشاشة الرئيسية / تثبيت التطبيق**.
3. بعد التحميل الأول، يعمل التطبيق بالكامل **دون اتصال بالإنترنت**.

### على Samsung Internet
1. افتح رابط التطبيق عبر HTTPS.
2. اضغط أيقونة التنزيل/التثبيت في شريط العنوان أو القائمة (**☰ → إضافة الصفحة إلى → الشاشة الرئيسية**).
3. ملاحظة: بعض إصدارات Samsung Internet لا تدعم امتداد `WebAuthn PRF` بعد؛ ستكشف خزنة ذلك تلقائياً وتُعلمك بوضوح قبل عرض وضع الراحة أو الاكتفاء بكلمة المرور الرئيسية.

## ٥. النسخ الاحتياطي، الاستيراد، والاسترداد

- **تصدير `.vault` مشفّر (موصى به)**: ملف JSON موثّق ومشفّر بالكامل باستخدام Argon2id/PBKDF2 + AES-256-GCM يمكنك حفظه على Drive أو فلاشة أو عبر مشاركة Android.
- **الاستيراد الذكي**:
  - يدعم **Samsung Pass (`.spass`)** مع فك تشفير AES-256-CBC + PBKDF2-SHA256 (70,000 دورة) ومحلّل مرن يتحمل الفواصل والأسطر المتعددة والبطاقات الجزئية، بالإضافة لتصدير `.spass` (بأفضل جهد لعدم وجود مواصفة رسمية من سامسونج).
  - يدعم **Bitwarden JSON**، **خزنة JSON**، **JSON عام**، وملفات **CSV** من Chrome و Edge و Firefox و Safari و Bitwarden و 1Password و KeePassXC و LastPass بالإضافة إلى **أداة ربط الأعمدة اليدوية** لأي ملف CSV آخر.
  - يعرض معاينة قبل الاستيراد مع كشف التكرارات (تخطي / دمج / استبدال / احتفاظ بالاثنين)، وربط المجلدات بالأقسام، ويأخذ لقطة احتياطية مشفّرة تلقائياً قبل الحفظ.
- **مزامنة بين الأجهزة بدون سحابة (رابط أو كود مشفّر)**:
  - من زر **«مزامنة»** في الشريط العلوي (أو من الإعدادات)، يمكنك إنشاء رابط بضغطة واحدة (`#sync=...`) أو كود نصي (`KHAZNA-SYNC-1:...`) مضغوط بـ gzip ومشفّر بـ **PBKDF2-SHA-256 (600,000 دورة) + AES-256-GCM** لأحدث التعديلات فقط أو للخزنة كاملة.
  - البيانات المشفّرة تُوضع داخل جزء الرابط `#sync=` فقط (لا يُرسل أبداً للخادم ولا يحتوي على كلمة المرور)، وعند فتح الرابط على جهازك الآخر يقوم التطبيق بمسح الرابط من شريط العنوان فوراً وتعبئة الكود تلقائياً في مكانه وعرض معاينة الفروقات والدمج الذكي (الأحدث تاريخاً يفوز مع لقطة تراجع مشفّرة تلقائية).
- **الاسترداد في حالة نسيان كلمة المرور الرئيسية**:
  - من شاشة القفل اضغط **نسيت كلمة المرور؟ استرداد بالمفتاح**، وأدخل مفتاح الاسترداد ذو الـ ١٤ مجموعة لتعيين كلمة مرور رئيسية جديدة مع إعادة لف الـ DEK ذرياً.

## ٦. تشغيل الاختبارات وتوليد بصمة السلامة وحزمة ZIP

لا حاجة لأي تبعيات خارجية لتشغيل الاختبارات (Node.js 22+ فقط):

```bash
# تشغيل جميع اختبارات التشفير والتخزين والمصادقة والمزامنة والاستيراد/التصدير
npm test

# تحديث بصمة SHA-256 لملفات التطبيق في app-integrity.json بعد أي تعديل
npm run integrity

# بناء حزمة التطبيق الساكنة النظيفة khazna-pwa.zip الجاهزة للنشر
npm run zip
```

### تسريع Argon2id عبر WASM محلي اختياري (بدون CDN)
تأتي خزنة بمحرك **Argon2id (RFC 9106)** مدمج بالكامل بـ JavaScript نقي يعمل داخل Web Worker لكي لا يتجمد التصميم، ولا يحتاج أي ملفات خارجية.
إذا أردت إضافة وحدة Argon2id WebAssembly محلية اختيارية لسرعة أعلى على الهواتف الأقدم:
1. ضع الوحدة المُجمّعة محلياً في `vendor/argon2.esm.js` و `vendor/argon2.wasm` مع تصدير دالة `argon2id({ pass, salt, time, mem, parallelism, hashLen })`.
2. تحقّق من بصمة `SHA-256` للملف قبل تضمينه ودوّنها هنا وفي `app-integrity.json`.
3. لا توجد حالياً أي حزم خارجية مُضمّنة في `vendor/` (صفر تبعيات خارجية في وقت التشغيل).

## ٧. نموذج التهديد وحدود المنصة (بكل صراحة)

تلتزم خزنة بعدم تزييف أي ميزة أمان:

- **لقطات الشاشة (Screenshots / Screen Recording)**: تطبيقات الويب و PWA لا يمكنها تفعيل علم `FLAG_SECURE` في نظام Android لمنع لقطات الشاشة. توفّر خزنة غطاء تمويه خصوصية عند فقدان التركيز أو الخروج للتبديل بين التطبيقات كحماية بأفضل جهد فقط.
- **مسح الحافظة (Clipboard Auto-Clear)**: بعد نسخ أي كلمة مرور تحاول خزنة مسح الحافظة بعد المهلة المحددة (افتراضياً ٣٠ ثانية)، لكن على Android قد يفشل المسح إذا كان التطبيق في الخلفية، كما أن **سجل الحافظة في لوحة المفاتيح (مثل Gboard أو Samsung Keyboard)** لا يمكن لتطبيقات الويب حذفه. يُنصح بتعطيل مزامنة سجل الحافظة أو حذف اللقطات يدوياً.
- **تصفير الذاكرة في JavaScript**: تقوم خزنة بتصفير مصفوفات البايت (`Uint8Array.fill(0)`) وإسقاط المراجع عند القفل، لكن النصوص (`string`) وجامع القمامة (GC) في محرك المتصفح لا يضمنان المسح الفوري من ذاكرة RAM على مستوى العتاد.
- **تنسيق Samsung Pass (`.spass`)**: تنسيق غير موثّق رسمياً من سامسونج وقد يتغيّر بين الإصدارات؛ لذا صُمم المحلّل والمصدّر ليكونا مرنين مع تحذير واضح بالتجربة عند التصدير.
- **المسح بعد N محاولات فاشلة**: معطّل افتراضياً ويحذف البيانات المخزّنة في IndexedDB فقط (لا يمكنه حذف ملفات النسخ الاحتياطي التي صدّرتها مسبقاً).

للتفاصيل التشفيرية الكاملة راجع ملف [`SECURITY.md`](./SECURITY.md).
